# 《艙底種火》第一章母艦序章設計

> 日期：2026-07-13  
> 狀態：已核准  
> 範圍：`03_SCENE_PIPELINE/3d-prototype/`；不修改小說正文或閱讀器

## 1. 設計目標

依小說第 1 章的故事順序，把現有的通用收集原型重做成約 15–20 分鐘的第一人稱生存敘事序章。玩家應先感受到艙底居民的缺氧與欠稅壓力，再逐步理解自己身處一艘仍在太空航行、規模巨大且持續老化的母艦。

核心體驗不是戰鬥或收集，而是：

- 在時間、氧氣、身體負荷與維修品質之間取捨。
- 親手收到無法償還的四十點欠額與七十二小時清退倒數。
- 在黑市以有限籌碼接受高風險裂縫任務。
- 從封閉的母艦腹腔走到外環，第一次看見巨艦與太空尺度。

## 2. 體驗支柱

### 2.1 母艦腹腔

配電槽、走廊與黑市不靠大量舷窗表現太空感，而以弧形艦殼、生命維持管線、氣密結構、垂直維修深井、姿態修正與艦體低頻震動建立「住在機器體內」的感覺。

### 2.2 制度生存壓力

氧氣、欠額和倒數不是一般遊戲血條。資訊主要由磨損腕環、公共終端、廣播與環境反應傳達。玩家的行動目標來自制度逼迫，而不是漂浮的任務標記。

### 2.3 尺度延後揭露

前段限制視野，只讓玩家從格柵與維修井窺見艦體縱深。外環氣密門開啟後，才展示彎向遠方的巨大灰白艦殼、結構深淵、航行燈、星空與裂縫，形成第一章視覺高潮。

## 3. 章節流程

```text
第九段配電槽限時維修
  -> 潮濕走廊與公共終端欠稅通知
  -> 廢棄減壓艙黑市談判
  -> 第七投放帶整備
  -> 外環氣密門開啟
  -> 踏入裂縫，章末結束
```

### 3.1 配電槽

玩家在狹窄管線間完成三段維修：定位短路、固定接頭、拉下備援閥。操作太快會增加受傷與義腿負荷，太慢會消耗氧氣並引發艙段停氧警告。成功後，指示燈由紅轉黃再轉綠，遠處艙段同步恢復供電。

### 3.2 公共終端

玩家穿過模組化弧形走廊，看到稅務封條、排隊居民與失效燈管。腕環掃描後，終端逐項顯示二十七點歷史欠額、九點附加稅、四十點最低需求與七十二小時限期。這一幕建立全章主要壓力。

### 3.3 黑市

黑市位於廢棄減壓艙。玩家與蘇嵐進行短談判，只能優先取得報酬、情報或藥劑中的部分利益。選擇會成為下一章裂縫任務的初始狀態，但不改寫小說的必要結果：林燼接下任務。

### 3.4 第七投放帶

玩家檢查腕環任務、義腿狀態與藥劑，聽取賀鐵規則。氣密門開啟後完成母艦尺度揭露；玩家接近裂縫時，胸前金屬薄片升溫，最後主動踏入藍白電弧。

## 4. 技術架構

原型維持 Vite、Three.js 與原生 HTML/CSS/JavaScript，避免在垂直切片階段引入大型遊戲框架。

- `PrologueDirector`：管理章節節拍、場景狀態與必要進程。
- `MothershipWorld`：建立可重用的艦殼、走廊、格柵、管線、氣密門與外環模組。
- `InteractionSystem`：以視線射線和距離判斷世界內互動，取代靠近即觸發。
- `SurvivalState`：管理氧氣、維修品質、義腿負荷、欠額與倒數等可序列化狀態。
- `DiegeticUI`：管理腕環、終端畫面、環境標誌與必要的 HTML 無障礙替代介面。
- `AudioDirector`：依所在艙段混合低頻艦鳴、管線、呼吸、氣密門與外部真空感。

場景流程由明確狀態機驅動，不用散落在更新迴圈中的條件判斷。所有關鍵敘事文字以第 1 章讀者安全資料定義，避免洩漏後續內容。

## 5. Three.js 與 HTML 的責任界線

Three.js 負責玩家相信「存在於世界內」的元素：

- 艦體與道具幾何、材質、燈光、粒子和陰影。
- 腕環投影面、公共終端螢幕、狀態燈與環境標誌。
- 艦體震動、姿態修正、冷凝水、壓力霧與外部星空慢速位移。
- 互動目標的實際位置、朝向、遮擋與動畫。

HTML/CSS 負責清晰性與可用性：

- 開始、暫停、設定、字幕、教學與章末畫面。
- 鍵盤操作提示及必要的無障礙文字鏡像。
- 開發階段診斷資訊；正式遊玩時預設隱藏。

不保留固定左上任務欄、一般污染血條或漂浮收集數量。世界內資訊失效時，HTML 介面仍提供可選的高可讀模式。

## 6. 素材優先級

### P0：建立場景語言

- 弧形走廊、格柵深井、管線、配電槽、備援閥與氣密門。
- 模組化燈管、狀態燈、艙段編號與管線標示。
- 腕環、公共終端與裂縫入口代理模型。
- 艦殼外環、遠景結構、航行燈與星空背景。

### P1：建立母艦生命感

- 供電連鎖閃爍、艦體微震與推進器脈衝。
- 冷凝水、水滴偏移、壓力霧與維修粉塵。
- 格柵深處移動燈光與巨大結構陰影。
- 氣密門開啟與外部聲場轉換。

### P2：角色與細節

- 林燼手部、磨損腕環與義腿第一人稱回饋。
- 程領班、排隊居民、蘇嵐、賀鐵及隊員的代理角色。
- 稅務封條、透明晶片、灰藍藥劑與黑市玻璃罐。

## 7. 資料流與存檔

互動輸入先由 `InteractionSystem` 轉成語意事件，再交由 `PrologueDirector` 驗證當前節拍是否允許。通過後更新 `SurvivalState`，世界動畫與 UI 訂閱狀態變更。章末輸出可序列化結果，供裂縫場景讀取。

開發初期只保存章節內檢查點，不做完整存檔系統。重新載入可從目前節拍開頭恢復，避免玩家因瀏覽器刷新重做整章。

## 8. 錯誤與降級

- GLB、紋理或音效載入失敗時使用程序化代理素材，不阻止遊玩。
- WebGL 能力不足時降低陰影、霧、粒子和後處理品質。
- Pointer Lock 被拒絕時顯示明確操作提示並允許再次啟動。
- 關鍵互動若因遮擋無法瞄準，提供近距離鍵盤候選目標作為降級。
- 所有失敗以開發警告記錄；不把內部錯誤文字顯示給一般玩家。

## 9. 驗證標準

- 玩家能依小說順序完成四個主要節拍並踏入裂縫。
- 沒有收集五個發光物或固定污染血條的舊玩法。
- 在未讀說明文字的情況下，測試者能辨認場景位於太空母艦。
- 外環揭露前保持封閉，揭露後能看到艦殼曲率、結構縱深與有限星空。
- 欠額、氧氣與義腿狀態主要由世界內介面和感官回饋傳達。
- 桌面瀏覽器可完成流程；素材缺失時仍可用代理物件通關。
- 所有繁體中文文字檔案為 UTF-8 無 BOM。
